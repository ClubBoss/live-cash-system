## Purpose

Create a durable repository-based handover so a new chat or agent can continue from accepted project truth without a manual history recap, broad repository scan or repeated project diagnosis.

The user can now begin a fresh chat with:

```text

```

No manual project recap should be required while repository access is available.

## Expected new-chat behaviour

The new chat should:

- verify live `main`;
- read the bootstrap cone, not the whole repository;
- identify the current checkpoint and active milestone;
- preserve frozen identities and accepted closures;
- select one highest-EV bounded next step;
- continue rather than restart;
- update handover state after a material checkpoint.

## Quality gates passed

The bootstrap cone answers:

- final product and learner target;
- source completeness and remaining continuity;
- stable architecture and IDs;
- current counts;
- active milestone and open gates;
- authority order;
- forbidden scope;
- next action;
- required maintenance after completion.

## What remains intentionally outside the handover

The handover does not duplicate:

- full canonical transcripts;
- every historical report;
- all 34 candidate descriptions;
- every question-row detail;
- proprietary source examples;
- archive/deprecated material.

It links to the active authority cone instead.
