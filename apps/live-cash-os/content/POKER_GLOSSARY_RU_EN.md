# Live Cash OS — RU/EN Poker Glossary and Editorial Standard

Status: `WAVE_2_GOVERNANCE_ACTIVE`

This glossary controls learner-facing terminology. It does not prohibit ordinary poker English. It prohibits unexplained hybrid architecture language that increases cognitive load.

## 1. Voice

### Russian

- Short, practical, poker-native sentences.
- Prefer the decision the learner can execute at the table.
- Use an English poker term in parentheses only when it improves recognition in courses, software, or live discussion.
- Standard poker vocabulary is not a defect. On first meaningful use, pair a term with a short plain-Russian explanation when a less experienced learner may not know it; later uses may stay poker-native.
- Do not translate one term differently across modules without a strategic reason.
- Do not expose internal words such as `gate`, `node signature`, `source range`, `evidence probe`, or `measurement context` as unexplained learner copy.

### English

- Natural contemporary poker English, not a literal translation of Russian syntax.
- Prefer concrete branch language over research jargon.
- Preserve the same assumptions, uncertainty, and strategic boundary as Russian.
- Use US spelling consistently unless a fixed source title requires otherwise.

## 2. Preferred terms

| Concept | Preferred Russian | Preferred English | Usage rule |
|---|---|---|---|
| effective stack | эффективный стек | effective stack | Explain that it is opponent-specific in multiway pots. Do not say “effective depth” when the chip amount itself is meant. |
| effective depth | эффективная глубина | effective depth | Use for the strategic depth expressed in BB/straddles, not as a synonym for the raw stack amount. |
| stack-to-pot ratio | SPR / отношение стека к банку | SPR / stack-to-pot ratio | Introduce the full meaning once; `SPR` is acceptable thereafter. |
| range | диапазон | range | `Рейндж` is allowed only in quoted table speech or where the owner explicitly prefers it. Default learner copy uses `диапазон`. |
| IP / OOP | IP (в позиции) / OOP (вне позиции) | IP / OOP | On first meaningful use, expose the abbreviation with its Russian meaning. After that, `IP`/`OOP` are useful poker-native shorthand. Do not use hybrids such as `OOP discomfort` as an explanation. |
| heads-up | хедз-ап (один на один) | heads-up / HU | First meaningful use makes “one on one” explicit; later `хедз-ап` or `HU` is acceptable. Do not replace every occurrence with a long бытовой paraphrase. |
| multiway | мультивей (банк на троих и более) | multiway | First meaningful use makes the player count clear; later learner copy should normally use `мультивей`, not repeatedly spell out “банк на троих и более”. |
| range-bet | range-bet (ставка почти всем диапазоном) | range bet | Introduce the practical meaning once; later `range-bet` is acceptable when the lesson has already established it. Do not expose abstract `range construction` or other research-language hybrids. |
| nuts | натс / натсы | nuts | Standard poker term. Define as the strongest possible hand(s) in the current context when first introduced to a novice; retain `натс/натсы` afterward. |
| nut blocker | натсовый блокер | nut blocker | Standard poker term. Explain which nut-value combinations it removes and whether it also removes bluffs; do not reduce the decision to blocker prestige. |
| equity realisation | реализация эквити | equity realisation | Avoid bare `realisation` in Russian. Explain which future actions prevent the hand from realising equity. |
| squeeze | сквиз | squeeze | Standard poker loanword; define the players and dead money rather than saying “squeeze branch”. |
| blocker | блокер | blocker | The card-removal effect must be linked to credible value/bluff combinations. |
| denial | лишение эквити / выбить долю эквити | equity denial | Use the shorter form that fits the sentence; do not use unexplained `denial`. |
| value bet | ставка на вэлью | value bet | State the worse hands expected to continue. |
| value raise | рейз на вэлью | value raise | State the worse continuing region and stack-off implications. |
| bluff | блеф | bluff | State the fold target and relevant blockers when material. |
| bluff-catcher | блеф-кетчер | bluff-catcher | Define as a hand that mostly beats bluffs, not value. |
| linear range | линейный диапазон | linear range | Strongest hands continue in one contiguous value-heavy region. |
| polar range | полярный диапазон | polar range | Strong value plus bluffs; do not imply perfect equilibrium composition. |
| condensed range | сжатый диапазон | condensed range | Explain that the strongest region is partly missing and medium-strength hands dominate. |
| capped range | ограниченный сверху диапазон | capped range | `Капнутый` may appear secondarily in parentheses; primary copy should explain what strong hands are absent. |
| protected flat | защищённый колл | protected flat | Explain which strong hands remain in the calling range and why. |
| cold-call | холодный колл | cold-call | Define as calling without having invested beyond a forced blind in the current raise sequence. |
| closing the action | закрывает торговлю | closes the action | State whether players remain behind. Avoid `closing-action gate`. |
| players behind | игроки за спиной | players left to act / players behind | Prefer the explicit phrase over `players-behind gate`. |
| source of the range | откуда пришёл диапазон | range source | In learner copy ask “кто и из какой позиции заколлировал?” rather than displaying `source range`. |
| branch | ветка розыгрыша / конкретная линия | branch | Use only when the action sequence is clear. Avoid abstract `branch construction`. |
| node | ситуация / точка решения | node / decision point | Russian learner copy normally uses `ситуация` or `точка решения`. `Node` is acceptable in internal provenance. |
| straddle | страддл | straddle | State whether mandatory/live and use the correct strategic unit. |
| baseline | базовая линия | baseline | A default under explicit assumptions, not a claim of universal GTO. |
| exploit | подстройка | exploit / adjustment | Russian copy should name the observed leak and confidence; avoid using `эксплойт` alone as an explanation. |
| population read | наблюдение о поле | population read | State sample, branch relevance, and alternative explanations. |
| heuristic | ориентир / практическое правило | heuristic | Russian learner copy prefers `ориентир`; every heuristic needs a boundary. |
| pocket pair | карманная пара | pocket pair | Structural family such as TT: a made pair with set potential. The family does not prescribe an action. |
| suited connector | мастевая связка (suited connector) | suited connector | Adjacent ranks of one suit, such as 76s or 98s. Teach suitedness/connectivity as traits, never “suited connector = call.” |
| suited wheel ace | мастевой туз колеса | suited wheel ace | A2s–A5s-type structure: ace blocker, nut-flush potential, and wheel connectivity. Blocker value does not manufacture a bluff. |
| suited Broadway | мастевой бродвей | suited Broadway | Two Broadway ranks of one suit, such as KTs. High-card structure plus suitedness does not imply an automatic continue. |
| offsuit Broadway | разномастный бродвей | offsuit Broadway | Two Broadway ranks of different suits, such as KJo. Explain high-card/top-pair potential together with domination sensitivity and lack of suitedness. |
| changed-node transfer | применение в изменённых условиях | changed-node transfer | Learner copy should describe the changed detail, not the internal measurement term. |
| boundary case | граница правила | boundary case | Show a case where the default no longer applies. |
| repair | работа над ошибкой | repair | `Repair` remains internal; learner copy says what error is being corrected. |
| delayed review | повторение после паузы | delayed review | Explain why the delay matters; do not show `retention queue`. |
| retention | удержание после паузы | retention | Use as an internal/summary term only after plain explanation. |
| field evidence | подтверждение на разобранных реальных руках | reviewed field evidence | A raw note or one result is not evidence of correct transfer. |
| confidence calibration | соответствие уверенности качеству решения | confidence calibration | Avoid bare `calibration` in Russian navigation. |
| insufficient information | данных недостаточно | insufficient information | A valid answer only when the stated information genuinely cannot select a responsible line. |

## 3. Prohibited learner-facing constructions

The following are not admissible as unexplained Russian learner copy:

- `Players-behind gate`;
- `Value squeeze core`;
- `protected flat branches`;
- `source ranges`;
- `fold targets` without naming the hands expected to fold;
- `arriving ranges`;
- `node signature`;
- `branch construction`;
- `credible bluff supply` without counting or describing credible bluffs;
- `structural prior`;
- `directional shift` without saying what changes and why;
- `OOP discomfort не заменяет анализ realisation`;
- `evidence gate`, `probe`, `measurement context`, or raw state-machine labels in primary UI.

These phrases may appear in internal governance or code when they are the precise implementation term. Standard poker terms such as `OOP`, `range-bet`, `натсы`, `блокер`, `блеф-кетчер`, `мультивей` and `хедз-ап` are not prohibited when their first meaningful use is scaffolded and the surrounding sentence remains understandable.

## 4. Copy rules

### Theory

- One paragraph = one mechanism.
- Lead with the decision problem, then the reason.
- Separate baseline, exploit, and exception.
- Avoid exact frequencies unless the source and assumptions support them.

### Heuristics

Every heuristic must contain:

1. observable trigger;
2. default action or direction;
3. reason;
4. boundary or exception.

### Questions

- Include all material assumptions.
- Ask for one decision at a time.
- Do not make the correct option longer, more precise, or more cautious by default.
- Use “данных недостаточно” only when it is genuinely the best answer.
- Do not state the exact strategic branch in a premise if that branch is what the item claims to test.
- A concrete combo may be classified by family/traits without creating a new chart cell; family recognition and strategy selection remain separate tasks.

### Explanations

- Explain why the preferred action works.
- Name the range or hand class affected.
- State what would change the answer.
- Do not merely repeat the option text.
- For concrete-hand examples, prefer the chain `combo → family/traits → context → decision` over memorised combo-to-action rules.

### Calls to action

Use user intent:

- `Начать проверку` rather than `Запустить T1`;
- `Потренироваться` rather than `Open probe`;
- `Сохранить руку для разбора` rather than `Submit field evidence`.

## 5. Locale parity

RU and EN must share:

- stable module, claim, drill, option, and card IDs;
- the same correct action and reason;
- the same assumptions and exceptions;
- the same uncertainty level;
- the same admission status.

They do not need identical sentence structure. Naturalness is evaluated independently.

## 6. Approval rule

A language version is approved only after an explicit poker-aware read in full module context. Spellcheck, lint, hash locks, deterministic tests, and machine/AI review are rejection tools, not approval tools.
