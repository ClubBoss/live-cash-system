## Severity ledger

### P0 — none currently known in the accepted platform scope

A new P0 is created immediately for any confirmed learner-state loss, invalid strategic admission, security/privacy breach, or production-unavailable defect.

### P1 — blocks a relevant wave from acceptance

- unclear product/T1 purpose;
- any unreviewed strategic module represented as approved;
- ambiguous or numerically invalid drill;
- material RU/EN meaning mismatch;
- inaccessible primary learner workflow;
- silent state conflict or unrecoverable import failure;
- false mastery or field-validation transition.

### P2 — polish or evidence debt

- non-critical microcopy inconsistency;
- minor visual-density issue;
- incomplete optional debug information;
- missing release tag or package-version synchronization;
- external authenticated production smoke pending;
- evidence not yet available because real learner use has not occurred.

## Governing acceptance rule

A wave is accepted only against its current Master Wave Plan DoD. Automated checks may reject invalid work but cannot create poker-content, RU/EN editorial, accessibility, production-authenticated, or empirical-learning approval by themselves.
