# Live Cash System — Adaptive Module Readiness Manifest v0.1

Status: `ACTIVE_READINESS_SSOT / 11_MODULES_ASSESSED`

## Purpose

Track readiness of each stable adaptive module across independent dimensions.

A module is not simply ready or blocked. It may be:

- mechanism-ready;
- explanation-ready;
- boundary-incomplete;
- drill-incomplete;
- anchor-dependent;
- exploit-field-pending;
- learner-runtime-ready.

This manifest prevents a missing exact chart from blocking robust reasoning and prevents source completeness from being mistaken for learner readiness.

## Readiness dimensions

| Dimension | Meaning |
|---|---|
| `MECHANISM` | robust strategic direction is source-supported |
| `EXPLANATION` | compact original explanation exists |
| `BOUNDARIES` | exceptions and context splits are sufficiently explicit |
| `DIAGNOSTIC` | misconception and baseline diagnostic coverage exists |
| `DRILLS` | original direct and contrastive drills exist |
| `RETENTION` | delayed variants and table cue can be scheduled |
| `ANCHORS` | exact ranges/sizes required for execution are independently available |
| `OVERLAYS` | opponent/environment branches have evidence grades and falsifiers |
| `FIELD` | real-session observation and repair loop exists |

Readiness values:

- `READY`
- `WORKING`
- `PARTIAL`
- `PENDING_SOURCE`
- `PENDING_ANCHOR`
- `PENDING_FIELD`
- `NOT_REQUIRED`
