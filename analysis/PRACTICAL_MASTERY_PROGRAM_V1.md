# Live Cash OS — Practical Mastery Expansion Program V1

Status: `ACTIVE / OWNER_AUTHORIZED / FEATURE_FREEZE_EXCEPTION_BY_REAL_USE_P1_LEARNING_DEFECT`

## Mission

Re-found Live Cash OS from a compact 11-module mechanism course into a practical live-cash NLHE decision-training system optimized for becoming a very strong live-cash player.

The governing rule is:

`MINIMUM COMPLEXITY SUBJECT TO NO MATERIAL LEARNING-EV LOSS`

The legacy 11 LCMs remain valid conceptual authorities where source-supported, but they are no longer a curriculum-size ceiling.

## Owner authorization

The owner explicitly authorizes:

- expansion beyond 11 modules;
- materially longer curriculum when learning EV justifies it;
- adding large practice families and controlled variants;
- resetting learner progress if the re-founded curriculum makes old completion/mastery topology semantically misleading;
- completing Waves 0–14 as one continuous gauntlet program without manual approval stops unless a critical blocker is found.

This does not authorize production deployment or synthetic human approval.

## Program execution contract

Each wave follows:

`audit -> source lock -> implement -> adversarial review -> repair -> DoD -> next wave`

No manual pause is required between waves when DoD is satisfied.

Stop only for:

1. `STRATEGY_UNRESOLVED` — source conflict or insufficient answer-key support;
2. `ARCHITECTURE_DECISION_REQUIRED` — a material long-term architecture trade-off cannot be safely resolved from existing authority;
3. `REGRESSION_BLOCKER` — a critical regression cannot be safely repaired inside the wave;
4. `SCOPE_INVALIDATED` — evidence shows the remaining program topology must materially change.

## Wave map

### W0 — Skill Graph / Curriculum Re-foundation
Create the canonical live-cash skill graph, module taxonomy, prerequisite topology, source mapping, mastery evidence requirements and practice-family contract. Legacy LCMs become conceptual spine nodes rather than the entire course.

### W1 — Math / Equity / Combo Competency Gate
Pot odds, required equity, break-even thresholds, raw vs realised equity, implied/reverse implied odds, outs quality, combo counting, removal and blocker mechanics. Prior knowledge may test out through competency gates.

### W2 — Full Practical Preflop Tree
RFI by position, limps/isolation, IP calls, BB calls, SB decisions, 3-bets, facing 3-bets, 4-bet basics, squeeze trees, size/depth/context variants.

### W3 — Blind Mastery
BB versus opens by position/size, SB versus opens, SB first-in, BB versus SB open/limp, blind-vs-blind postflop and depth variants.

### W4 — Board + Hand-Family Recognition Engine
Board classes, runout classes, made-hand families, draw families, relative strength, vulnerability and concrete-hand-to-family transfer.

### W5 — Single-Raised Pots OOP
Range checking, check-call/fold/raise, c-bet defence by size, leads, delayed aggression, turn leads, river blocks/bluff catches and OOP realization.

### W6 — Single-Raised Pots IP
C-bet/check-back, selective vs range betting, delayed c-bets, floats, turn barrels, capped-range attacks, thin value and overbet branches.

### W7 — Complete 3-Bet Pot Matrix
Aggressor IP/OOP and caller IP/OOP across major board classes, sizing branches, turn/river continuations and stack-off thresholds.

### W8 — 4-Bet Pots + Low-SPR Play
4-bet-pot compression, AK/QQ/JJ/A5s families, relative polarisation, protected checks, small bets, jam exposure and low-SPR turn/river planning.

### W9 — Turn Mastery
Blank/scare/overcard/draw-completing/paired turns, barrel selection, probes, leads, delayed c-bets, check-raises, pot control, thin value and river setup.

### W10 — River Mastery
Value targets, thin value, bluff selection, bluff catching, blocker/unblocker logic, block bets, probes, overbets, jams and exploit under/overbluff adjustments.

### W11 — Multiway + Limp-Heavy Live Poker
Relative position, closing action, multiway value thresholds, bluff suppression, draws, overcalls, family pots, isolation, overlimps and limp-heavy live branches.

### W12 — Deep Stack + Straddle + Live Geometry
100/150/200/300bb+ selected nodes, implied/reverse implied odds, one-pair devaluation, leverage, stack-off thresholds, straddle position/SPR changes and deep live planning.

### W13 — Exploitative Live Cash
Player profiles, branch-specific evidence, population hypotheses, value/bluff/fold/call/sizing exploits, live timing/sizing evidence, table/seat/game-selection decisions.

### W14 — Integrated Player Engine
Topic-hidden mixed decisions, timed recognition, changed-node transfer, boundary cases, mistake-family repair, real-hand routing, delayed retention and full-player gauntlets.

## Cross-wave gauntlets

## Curriculum architecture

Canonical hierarchy:

`Source evidence -> Concept -> Skill family -> Subskill -> Lesson -> Anchor decision -> Controlled variants -> Transfer probe -> Delayed retrieval -> Real-hand evidence`

A concept is not considered trained merely because it appears in theory.

## Evidence states

Every skill-family row must distinguish:

- `SOURCE_SUPPORTED`
- `CONCEPT_TAUGHT`
- `RECOGNITION_TRAINED`
- `DECISION_TRAINED`
- `CHANGED_NODE_TRANSFER`
- `BOUNDARY_TESTED`
- `DELAYED_RETRIEVAL`
- `REAL_HAND_TRANSFER`

No later state may be inferred from an earlier one.

## Practice contract

A strong practical family should normally contain enough variation to cover:

- multiple concrete combos or hand classes;
- at least two materially different board/context states where applicable;
- changed position, sizing or depth when that variable changes the mechanism;
- plausible distractor parity;
- explanation after prediction;
- at least one changed-node transfer check;
- delayed retrieval eligibility.

Exact counts are not quotas. Add only as much complexity as material learning EV requires.

## Progress policy

Because this program materially changes the curriculum topology, preservation of legacy completion/mastery is no longer mandatory.

When the new graph becomes runtime-authoritative:

- old progress may be reset or migrated to `historical evidence` only;
- no legacy completion flag may imply mastery of newly added branches;
- schema/version change is allowed when required for truthful skill-family evidence;
- the reset must be explicit, deterministic and user-visible.

## Test and release boundary

Development may proceed without GitHub Actions. When executable local tests are unavailable in the current agent environment, the wave must record `LOCAL_EXECUTION_UNAVAILABLE` rather than fabricate GREEN.

No production/release acceptance may rely only on static review. Before production, run a clean executable release suite or equivalent independent environment validation.

## Program terminal condition

The program closes only when:

- all live-cash-relevant P0/P1 skill families are mapped and trained to their intended evidence depth;
- cross-wave gauntlets pass;
- no material source-supported skill is lost through compression;
- mixed topic-hidden practice exists;
- real-hand routing maps mistakes back to skill families;
- no human approval or release claim is fabricated.

Terminal label:

`PRACTICAL_MASTERY_EXPANSION_COMPLETE / RELEASE_VALIDATION_STILL_SEPARATE`
